# Go Sanchari WhatsApp review invitations

This change builds on PR #28. Release migration 0024 before 0025. Keep automatic sending off until the bot workflow, sender permissions and approved templates have been tested.

## Bot workflow

1. Trigger only for a completed stay after checkout, with messaging permission. Use the booking code and WhatsApp number from trusted booking/CRM data. For an inbound request, use the sender number verified by the WhatsApp webhook, never a number typed into chat or generated by AI.
2. From a private workflow step, POST JSON to `https://gosanchari.com/integrations/review-bot/dispatch`:
   `{"booking_code":"GS-EXAMPLE","whatsapp_number":"+919000000000"}`.
   Supply `Authorization: Bearer <dedicated key>` from the workflow's secret store. Do not include the key, booking payload, or review tokens in the model prompt or execution logs.
3. Go Sanchari verifies the booking and recipient, then sends the approved template directly. Do not add a second WhatsApp Send node. The API returns status only, so the model never receives a review URL. Treat `not_eligible` and `not_issued` as a handoff to Staff. A duplicate result must not cause a new message.
4. `sent` means Meta accepted the message and returned its message ID, not that the guest's phone received it. `pending`, `failed`, and `skipped` need operator review. Inspect the provider's status before any manual resend. The service does not retry ambiguous sends and never overwrites staff-issued or revoked invitations.

The guest uses the existing WhatsApp OTP, review form and moderation flow. The bot cannot post a review on behalf of a guest.

## Release and enablement

- Verify production D1's migration ledger, active Worker, current recovery point, migration ordering, and PR checks before merging. Both migrations are additive; 0025 creates only the one-attempt-per-booking delivery ledger with timestamps, status and provider message ID. Existing reviews and bookings are untouched.
- Generate a dedicated random key of at least 32 bytes (base64url, unpadded). Store the raw key in the workflow credential store and its lowercase hex SHA-256 digest as Worker secret `REVIEW_BOT_KEY_SHA256`. Do not reuse a property API key.
- Configure `REVIEW_BOT_WHATSAPP_TEMPLATE` to the approved English invitation template on the same WhatsApp sender as the existing OTP flow. The template must accept exactly one body parameter (the full private URL), with no dynamic header or button. Example copy for template review: “Your Go Sanchari stay has ended. To share feedback, open your private review link: {{1}}. Thank you for staying with us.” Verify template category, approval, language and opt-in with the WhatsApp account owner.
- Verify the existing WhatsApp sender/token, approved OTP template and `SESSION_SECRET`. Configure production `SITE_URL` to the HTTPS public origin.
- Test using a controlled environment and consenting test number, including that WhatsApp preserves the URL fragment and the guest can verify and submit. Verify moderation and display without publishing a fake review on production.
- Only after readiness and permission are confirmed, set `REVIEW_BOT_SEND_ENABLED=true` and turn on the workflow. Unset it to stop dispatch without invalidating previously issued links.
